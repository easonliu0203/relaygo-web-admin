# 旅遊方案多語言管理指南

## 📋 功能概述

Web Admin 的旅遊方案管理頁面現已支援 8 種語言的多語言內容管理：

- 🇹🇼 繁體中文 (zh-TW)
- 🇺🇸 英文 (en)
- 🇯🇵 日文 (ja)
- 🇰🇷 韓文 (ko)
- 🇻🇳 越南文 (vi)
- 🇹🇭 泰文 (th)
- 🇲🇾 馬來文 (ms)
- 🇮🇩 印尼文 (id)

## 🎯 操作指南

### 1. 新增旅遊方案

1. 進入 **設定 > 旅遊方案管理** 頁面
2. 點擊右上角 **「新增方案」** 按鈕
3. 填寫基本設定：
   - **顯示順序**：數字越小越靠前（必填）
   - **啟用狀態**：開關切換（預設為啟用）

4. 填寫多語言內容：
   - **繁體中文（必填）**：至少需要填寫方案名稱和描述
   - **其他語言（選填）**：可稍後補充

5. 點擊 **「儲存」** 按鈕

### 2. 編輯現有方案

1. 在方案列表中找到要編輯的方案
2. 點擊 **「編輯」** 按鈕
3. 使用語言標籤頁切換不同語言：
   - ✅ 綠色勾號：該語言翻譯完成
   - ⚠️ 黃色警告：該語言部分完成
   - 無圖示：該語言尚未翻譯

4. 修改完成後點擊 **「儲存」**

### 3. 查看翻譯完成度

在方案列表的 **「翻譯完成度」** 欄位可以看到：
- **數字顯示**：例如 "6/8" 表示已完成 6 種語言
- **完成標籤**：✅ 完成（8/8）
- **百分比標籤**：⚠️ 75%（6/8）

### 4. 刪除方案

1. 點擊方案列表中的 **「刪除」** 按鈕
2. 確認刪除操作
3. 方案及其所有翻譯將被永久刪除

### 5. 啟用/停用方案

- 直接在列表中切換 **「狀態」** 開關
- 停用的方案不會在客戶端 App 中顯示

## 💡 最佳實踐

### 翻譯優先順序

建議按以下順序完成翻譯：

1. **繁體中文（必填）** - 系統預設語言
2. **英文** - 國際通用語言
3. **日文、韓文** - 主要客群語言
4. **東南亞語言** - 根據業務需求

### 翻譯品質建議

1. **保持一致性**：相同的景點名稱在不同方案中應使用相同翻譯
2. **文化適應**：考慮不同文化背景，調整描述方式
3. **長度控制**：避免翻譯後文字過長影響 UI 顯示
4. **專業審核**：建議由母語人士審核翻譯內容

## 🔧 技術說明

### 資料結構

```json
{
  "id": "uuid",
  "name": "台北一日遊",
  "description": "探索台北熱門景點...",
  "name_i18n": {
    "zh-TW": "台北一日遊",
    "en": "Taipei Day Tour",
    "ja": "台北日帰りツアー"
  },
  "description_i18n": {
    "zh-TW": "探索台北熱門景點...",
    "en": "Explore popular attractions in Taipei...",
    "ja": "台北の人気観光スポットを探索..."
  },
  "is_active": true,
  "display_order": 1
}
```

### API 端點

- **GET** `/api/tour-packages` - 獲取所有方案
- **POST** `/api/tour-packages` - 新增方案
- **PUT** `/api/tour-packages/:id` - 更新方案
- **DELETE** `/api/tour-packages/:id` - 刪除方案

### 語言參數

Mobile App 會根據用戶的語言偏好自動請求對應語言的內容：
- Query Parameter: `?lang=en`
- HTTP Header: `Accept-Language: ja`

## 📊 常見問題

### Q1: 如果某個語言沒有翻譯會怎樣？

A: 系統會自動使用以下後備機制：
1. 請求的語言（例如：日文）
2. 繁體中文（預設語言）
3. 原始欄位值
4. 空字串

### Q2: 可以只填寫部分語言嗎？

A: 可以。只有繁體中文是必填的，其他語言可以稍後補充。

### Q3: 如何新增第 9 種語言？

A: 需要修改程式碼中的 `SUPPORTED_LANGUAGES` 常數，請聯繫技術團隊。

### Q4: 翻譯內容會即時生效嗎？

A: 是的。儲存後，Mobile App 下次請求時就會獲取最新的翻譯內容。
